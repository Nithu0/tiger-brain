## Lessons learned (sprint-level, 80+ agenter)

1. **80 parallelle agenter er feasible** — dispatch + meta-verify + integration fungerte over 9 bølger. Kostnad: ~3 cycles av context per agent (~1.5M tokens totalt budsjett på tvers av orchestrator over 5 timer). Ingen agent-collisions takket være files_allowed-allowlists. **Konklusjon:** parallell-dispatch skalerer til 80+ hvis files_allowed + scope-cap er klart formulert per agent.

2. **Cross-spec verify (B-2 + G-3 + G-4) var essensiell** — B-2 fanget 7 CRIT som ville blokkert code-1. G-3 + G-4 i fase 7 verifiserte at fixes faktisk landet (cross-source consistency). Mønster: **spec → verify v1.1 → fix → re-verify v1.2**. Multi-pass cross-verify er ikke overkill — det er den eneste måten å unngå "specs sier X, kode bygger Y" drift.

3. **Live audit runs (G-1) fant ekte gaps som krevde bug-fix-runde (H-1 script + H-2 cleanup)** — F-9 brain-content-audit.sh hadde en step-5 bug som først ble synlig når G-1 kjørte den live mot full brain. Lesson: **scripts som "passerer egne tester" kan likevel ha bugs synlig kun mot full prod-data**. Live-run + post-run reconcile er kritisk.

4. **Reconciliation-passes (I-1 + I-2) trengs for cross-source consistency** — link-graph (H-8) sa 209 broken, wikilink-audit (G-3) sa 0 broken. Begge var korrekt — forskjellig definisjon (graph inkluderer orphans/relative paths, audit kun absolute wikilinks). Uten I-1 ville operator lest motstridende tall. Lesson: **multi-source claims trenger eksplisitt reconciliation-doc**, ikke bare individuelle rapporter.

5. **Async inbox-koordinering har ~5min Obsidian-Git lag** — code-1 leste stale inbox 12:45Z; løsning = re-read + eksplisitt clarification dispatch. For tids-kritisk hand-off, bruk feed.md (lavere lag) eller direkte pane-veksling. Lesson holder fra fase 1-3.

6. **Files_allowed-allowlist forhindrer agent-edit-konflikter** — når 80 agenter rører overlappende filer, distinkt fil-eierskap er ikke-forhandlingsbart. Bekreftet i fase 4-8: ingen edit-konflikter på tvers av 50+ samtidige agenter takket være eksplisitt scope-cap.

7. **Self-verify 5× per agent + meta-verify (5× checks på integrator-nivå) gir 2-tier kvalitets-gate** — fanget bge-m3 dim-feil (B-3 → A-7-catch), folder-kollisjon (B-1 → B-2-flag), wikilink-typo (C-10), F-9 step-5 bug (G-1-catch), gate-identity mismatch (H-9-catch). Uten tier-2 ville fase 1-8 vært spilt på code-1.

8. **Cleanup-runde må være additive, ikke rewriting** — H-2 fjernet 13 av 24 invalid YAML uten å røre eksisterende innhold (kun la til manglende frontmatter-felt). Lesson: **aldri rewrite gammelt operator-innhold, kun additive-patch**. 11 gjenværende invalid YAML er pre-eksisterende, ikke regression.
