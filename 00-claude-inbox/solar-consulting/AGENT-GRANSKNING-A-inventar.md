Repo: `/home/nithu/code/Veldora-sc04-agenter` @ `1f8d131` (worktree av origin/main). Bare lesing. Alle stier under er relative til `projects/anbud/crm/src/` med mindre annet er sagt (`dashboard/` = `projects/anbud/dashboard/src/`, `automation/` og `.github/` = repo-rot).

Metode: fire parallelle lese-agenter (jobs/tasks-kallsteder, lib-kallsteder, heuristikker, infrastruktur) + egne stikkprøver av de mest overraskende påstandene (embeddings-stub, «sonnet»-etiketter, ingest-answer-fingeravtrykk, stopReason, brief-terskler, sol-nøkkelord, backtest.ts, router-linjenummer). Én agent-påstand ble funnet feil og er rettet (se tabell 2, backtest.ts). Prod-miljøvariabler er ikke i repoet, så *faktisk* modell per task i drift er UNKNOWN der det står «LLM_MODEL ?? claude-sonnet-5».

## Felles fakta (gjelder alle rader i tabell 1)

- Ett eneste punkt mot modell-API: `lib/llm.ts` (`complete` :236, `streamComplete` :275, `completeJson` :487). Ingen SDK, rå `fetch` mot `https://api.anthropic.com/v1/messages` (:19) eller OpenAI-kompatibel `/chat/completions` (:208) når `LLM_PROVIDER=openai-compatible`.
- Ruting: `lib/llm/router.ts:47-50`: `LLM_MODEL_<TASK>` ?? `TASK_MODEL_DEFAULTS[task]` (`config/models.ts:114-143`) ?? `LLM_MODEL` ?? `claude-sonnet-5` (`router.ts:17`). Haiku-4.5-default for: extract.threshold, extract.criteria, extract.message, extract.answer, extract.cv, judge.classify, judge.fail-check, generate.news, generate.feilsjekk, route.helper, **generate.brief** (`models.ts:116-142`). `generate.answer` klemmes til minst Sonnet (`router.ts:40-45`, `models.ts:152-154`). Ingenting rutes til Opus som default (`models.ts:105`).
- TypeSafe/Jev (`lib/llm/typesafe.ts`, modell `jev-1.13.0` `models.ts:165`, POST `https://api.typesafe.ai/v1/systemone` `typesafe.ts:15`): bare dommer-primitiver (choice/noul/score), aldri tekst. Aktiv når `TYPESAFE_API_KEY` er satt, tasken har `primitive` + `dataClass: 'public'`, og står i `LLM_TYPESAFE_TASKS` (default `judge.classify`, `judge.citation`; `models.ts:160`, `router.ts:56-64`).
- Prompt-caching: **ingen**. `cache_control` finnes ikke i `crm/src` eller `dashboard/src` (grep). Request-body har bare model/max_tokens/system/messages (`llm.ts:176-181`). `models.ts:182`: «no cache or batch discount (we use neither)».
- Tool use: **ingen** i crm. Ingen `tools`/`tool_choice` i body; parseren beholder bare `type === 'text'`-blokker (`llm.ts:189-192`).
- maxTokens default 4096 (`llm.ts:236`); timeout 25 ms/token, 60 s–300 s (`llm.ts:32-33`); 3 retries på 429/529/5xx, timeout retryes én gang (`llm.ts:24-26,389-422`).
- Input-trunkering: hver melding kuttes til 60 000 tegn med markør (`INPUT_CHAR_BUDGET` `llm.ts:21`, `truncate` :160-164, brukt :180/:216). Dette er en **stille** global grense i tillegg til kallstedenes egne budsjetter.
- `completeJson` = 1 kall + 1 reparasjonsrunde ved ugyldig JSON/zod (`llm.ts:487-507`). Ingen andre selvkorreksjonsløkker i llm.ts.
- `stopReason` (max_tokens-kutt) leses bare ett sted i hele crm: `lib/legal/ask.ts:176`. Alle andre kallsteder ignorerer om svaret ble kappet.
- Datapolicy-port: `assertDataPolicy` (`llm.ts:144-155`) sjekker `TASK_DATA_TYPES[task]` (`models.ts:65-91`) mot `data-policy`-globalen. Task uten deklarasjon nektes (`UndeclaredDataError` :109). Degradert modus (policy kan ikke leses): bare `anbudsdokument` og `intern` slipper gjennom (`lib/datapolicy.ts:52-61`), dvs. alle cv/whatsapp/kunde-epost-tasks blokkeres da. Normal policy er permissiv (`datapolicy.ts:40`, `:95` default allowed). Om noe faktisk er blokkert i prod: UNKNOWN (ligger i DB).
- Hver kjøring logges som én `agent-runs`-rad via `withAgentRun` (`lib/agentRun.ts:23-79`); `WORKER_DRY_RUN=1` skriver ingenting (:5). Hvert modellkall logges som én `llm-usage`-rad (`llm.ts:253-266`, `lib/llm/usage.ts`).
