# Pipeline Reproducibility

What it takes to re-run the V4 pipeline and get the same numbers a year from now.

## Determinism

- `RANDOM_SEED=42` set globally — RF, train/test split, conformal calibration draw, kNN-OOD.
- All hyperparameters in `configs/v4.yaml` (verify path).
- Pipeline entry: `python run_pipeline.py --config configs/v4.yaml`.

## Pinned dependencies

- `requirements.txt` in sister-repo with version pins.
- matminer version pinned (Magpie feature count is version-dependent — see [[Magpie-Descriptors]]).
- `pytest tests/` must be green before commit per the project's `CLAUDE.md`.

## Versioned artefacts

- `data/processed/dataset_v4.csv` — committed.
- `models/rf_v4.pkl` — committed (pre-trained model checkpoint).
- `models/metrics.json` — generated by pipeline; copied into `Master-oppgave/results/thesis_metrics.json` per [[Sister-Repo-Relationship]] data flow.
- `reports/figures/*.png` — generated.

## Citation pattern

Every figure / table in the thesis traceable to a sister-repo commit:

```bash
cd ../battery-electrolyte-predictor && git rev-parse HEAD
```

→ embedded as `Code that produced Figure X.Y is available at github.com/Nithu0/battery-electrolyte-predictor at commit <hash>.`

This matters because the thesis is graded on reproducibility (rubric criterion). See [[Sister-Repo-Relationship]].

## What might break re-run-determinism

- matminer minor-version bump → Magpie feature count changes → feature-vector length changes → RF model not directly reusable.
- Materials Project API response evolution → MP-scalar values shift → re-cache invalidated.
- sklearn major-version bump → `GroupKFold` order can change.
