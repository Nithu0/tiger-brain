# Soking research-sweep — 2026-06-23

Web/video/forum-sveip for **Søking fulltid** (ML/AI/data-science jobbsøk). Domene: multi-board scraping, CV/ATS-optimalisering, søknads-CRM, company enrichment (brreg), compliance (draft-only, ingen LinkedIn-scrape/auto-apply). Mappet mot det vi alt har i `~/code/Søking fulltid/agent/`.

> Compliance-ramme (uendret): **draft-only**, operatøren sender selv. Ingen auto-apply. Ingen LinkedIn-scrape (auth + ToS). CV/søknader/lønnsforventninger = sensitivt, holdes lokalt, aldri eksternt.

## TL;DR — topp 5 å adoptere nå

1. **JobSpy (`python-jobspy`)** — én lib som scraper Indeed + Glassdoor med `country_indeed="norway"`, MIT. Gir oss Indeed-dekning vi mangler i dag uten å røre LinkedIn/ToS. *Why:* dekker hullet mellom finn + arbeidsplassen; standardisert output (CSV/df) som mater rett inn i `match_score.py`.
2. **brreg `python-brreg` company enrichment** — gratis åpen API, ingen auth, gir NACE-bransje, ansatt-tall, stiftelsesdato, konkurs/likvidasjons-status per org.nr. *Why:* løfter `enrich_leads.py` fra "tittel+sted" til ekte firma-kontekst → bedre scoring + bedre søknads-vinkling. Ren offentlig data, null PII-risiko.
3. **rendercv (YAML→PDF via Typst)** — én YAML-datafil → ekte tekst-PDF (ATS-parsebar), git-versjonerbar, MIT. *Why:* erstatter våre tre ad-hoc `cv_v2/v3_build.py` med én deklarativ kilde; flere CV-varianter fra samme data; diff-bar CV-historikk.
4. **Resume-Matcher (lokal Ollama-modus)** — match-score + keyword-gap + ATS-sjekk CV↔stilling, kan kjøre 100% lokalt via Ollama, Apache-2.0. *Why:* gir oss objektiv "hvilke keywords mangler CV-en for DENNE stillingen" før vi skriver utkast — direkte oppgradering av draft-loopen. Lokal = sensitivt CV forlater aldri maskinen.
5. **ai-job-scraper (BjornMelin) som arkitektur-referanse** — JobSpy + SQLite FTS5 + Streamlit + lokal LLM-ruting + hash-basert dedup. *Why:* speiler stacken vår nesten 1:1; ta ideene (FTS5-søk over annonser, content-hash dedup mellom scrape-runder, lokal/cloud token-threshold-ruting), ikke nødvendigvis koden.

## Hva vi ALT gjør (ikke re-implementer)

- Multi-board scraping: **arbeidsplassen.no** (NAV ES-proxy, ingen auth) + **finn.no** (HTML-parse) — `scan_arbeidsplassen.py`, `scan_finn.py`.
- ML-/regel-skåring 0–100 med tier-roller, lokasjon, seed-bedrifter, stopp-ord — `match_score.py`.
- Manuell enrichment av leads med URL — `enrich_leads.py`.
- CRM oppå `stillinger.xlsx` + read-only Streamlit (Tailscale-bound) — `crm_build.py`.
- Søknads-brev-rendering (PDF/Word) — `agent/soknad/render_letter.py`.
- Containerisert scanner for 24/7-noden.
- Draft-only + ingen LinkedIn/auto-apply (bevisst).

## NYTT verdt å vurdere (utover topp-5)

- **SQLite FTS5 over annonse-korpus** — fulltekst-søk + BM25-ranking, 5–300 ms på 500k rader. *Map:* alternativ/komplement til xlsx-CRM for rå-annonse-laget; gjør re-spørringer ("alle annonser m/ 'materials informatics'") trivielle. (fra ai-job-scraper)
- **Content-hash dedup mellom scrape-runder** — oppdag duplikat-annonser på tvers av kilder/dager, bevar bruker-data ved DB-oppdatering. *Map:* arbeidsplassen + finn overlapper ofte; vi mangler eksplisitt cross-source dedup.
- **Lokal cover-letter/CV-tailor via Ollama** (juancantor12/ollama-cv-builder, resume-llm/resume-ai) — henter JD fra URL, oppsummerer krav, matcher mot strukturert profil → DOCX, 100% lokalt. *Map:* fremtidig oppgradering av `soknad/`-laget når node-en står (Aug 2026); holder sensitivt CV lokalt. Pandoc→ATS-DOCX-trikset (resume-ai) er verdt å låne.
- **ATS-formattering-regler (2025)** — single-column, 0.75–1" marg, Arial/Calibri/Helvetica, .docx primær, full+akronym ("Natural Language Processing (NLP)"), 60–80% keyword-match uten stuffing, kvantifiser bullets. *Map:* kodifiser som lint-regler i CV-bygg + sjekk i Resume-Matcher-loopen.
- **Huntr / Teal (kommersielle CRM-er)** — kun som **idé-referanse**, IKKE adopter: kanban-pipeline, per-stilling lagret CV+brev, keyword-ekstraksjon fra JD, follow-up-scheduling/maler. *Map:* vår Streamlit-CRM kan låne kanban-view + per-stilling-artefakt-kobling + follow-up-påminnelse. (Autofill/auto-apply hopper vi over — bryter draft-only.)

## Eksplisitt IKKE adoptere

- **AIHawk / Auto_job_applier_linkedIn / ApplyPilot** — auto-apply-agenter. Bryter draft-only + LinkedIn-ToS. Discovery-only, avvist.
- **NAV pam-stilling-feed (Bearer-token-feed)** — krever registrering + skriftlig ToS-avtale, og roterende public-token. Vi bruker allerede den åpne search-proxyen; feeden er kronologisk/treg (alt forkastet i `project_state.md`). Bekreftet fortsatt auth-gated per 2026-06.

## Video-tips (transkribert 2026-06-23)

Tre soking-tagga transcripts ble distillert (alle tre handler om **RenderCV** — én er ren konseptuell intro, to er hands-on demoer). RenderCV-kjernen (YAML→PDF, content/design-separasjon, git-versjonering) er alt dekt i TL;DR #3 over — under er kun det som er **nytt og konkret** utover det.

- **JSON Resume → RenderCV via npx-converter.** Hold CV-dataene i den åpne JSON Resume-standarden og konverter til rendercv-YAML med én `npx`-kommando før render. *Why:* gir oss ÉN nøytral datakilde (JSON Resume) som både rendercv OG andre verktøy/hosting-registre kan konsumere — unngår lock-in til rendercvs eget schema hvis vi senere bytter renderer. *Source:* "Using JSON Resume to make a Latex resume with RenderCV" (sm6HF5JXTcQ). **Confidence: MED** (forfatterens eget converter-prosjekt, demo fungerte; de to dataformatene er "ikke fullt interoperable" iflg. ham selv — bytt-kost finnes).
- **HTML-output → lim inn i Grammarly for stave/grammatikk-sjekk.** RenderCV gir en `paste-to-grammarly.html` ved siden av PDF-en; ren tekst uten LaTeX-makroer, limes rett inn i Grammarly. *Why:* løser et reelt hull — LaTeX/PDF-CV kan ikke copy-pastes til stavekontroll pga. makro-støy; dette gir gratis korrektur-pass på søknads-engelsk før draft sendes til operatør. *Source:* "Automate your CV or resume with RenderCV" (0aXEArrN-_c). **Confidence: HIGH** (demonstrert ende-til-ende i video).
- **Bruk `publication`-entry-typen for thesis/papers.** RenderCV har 6 entry-typer (education/experience/publication/normal/online/text); `publication` er en førsteklasses type med påkrevd `title`. *Why:* direkte relevant for operatørens ML/DS-profil med masteroppgave + evt. paper — gir korrekt akademisk formatering uten håndhacking, og holder publikasjoner som strukturert data vi kan toggle av/på per CV-variant (industri vs. akademia). *Source:* (0aXEArrN-_c). **Confidence: HIGH**.
- **VS Code YAML-schema-workflow: Ctrl+Space-autocomplete + hover-hints + feil på ugyldige felt.** Installer YAML-extension; rendercvs JSON-schema gir feltforslag, dokumentasjon-on-hover og "property not allowed"-feil ved skrivefeil. *Why:* gjør YAML-redigering selvdokumenterende → lavere terskel for å vedlikeholde flere CV-varianter, færre stille feil. Bekrefter at rendercv-bygg bør være YAML-i-VS-Code, ikke en custom Python-builder. *Source:* (0aXEArrN-_c). **Confidence: HIGH**.
- **`show_timespan: true` per seksjon** auto-beregner varighet (f.eks. "2 yrs 3 mos") på experience-entries. *Why:* liten, men fjerner manuell vedlikehold av stillingslengder ved hver oppdatering. *Source:* (0aXEArrN-_c). **Confidence: MED** (theme-avhengig — vist på classic-theme).
- **r/EngineeringResumes-wiki som struktur-referanse for tech-CV.** Subreddit der ingeniører får CV-review; wikien beskriver anbefalt struktur. *Why:* gratis, named-community kilde til CV-struktur for tech-roller — komplement til ATS-2025-reglene vi alt har; nyttig som review-sjekkliste, ikke som scrape-mål. *Source:* "Using JSON Resume..." (sm6HF5JXTcQ). **Confidence: LOW-MED** (nevnt i forbifarten, ikke vist; verifiser wiki-innhold selv før bruk).
